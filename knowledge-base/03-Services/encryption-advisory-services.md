# Encryption Advisory Services

This article describes the Encryption Advisory Services offered by Encryption Consulting (EC). It explains what the service covers, how an engagement runs, what the customer receives, and what EC needs to get started. It is for security leaders, architects, and program managers who plan or improve an enterprise encryption program.

## What the service covers

Encryption Advisory Services help an organization decide how to protect sensitive data with encryption and how to manage the keys behind it. The service has four building blocks that can be used together or on their own:

- **Assessment:** review of current encryption, key management, and data protection controls. See [Encryption assessment](encryption-assessment.md).
- **Strategy:** a target state and a prioritized roadmap that match business, risk, and compliance needs.
- **Implementation:** hands-on help to deploy the chosen solutions and processes.
- **Audit:** an independent check that controls work as designed and match the written policy.

Related assessment options under this service include:

- **Encryption assessment:** finds gaps in encryption coverage, key management, and compliance.
- **Risk assessment:** looks at the risk of data exfiltration and proposes remediation.
- **Compliance assessment:** checks alignment with regulations and standards. See [Compliance advisory services](compliance-advisory-services.md).
- **Data discovery exercise:** maps where sensitive data lives across the environment.

## Who it is for

- Organizations starting an encryption or key management program for the first time.
- Organizations with many separate encryption tools and no single owner or policy.
- Teams preparing for an audit against standards such as the Payment Card Industry Data Security Standard (PCI DSS), the Health Insurance Portability and Accountability Act (HIPAA), the General Data Protection Regulation (GDPR), or the Cybersecurity Maturity Model Certification (CMMC).
- Teams that need to choose a new key management, tokenization, or encryption platform.

## Engagement phases

| Phase | Main activities | Output |
|---|---|---|
| 1. Project initiation | Gather requirements for encryption and key lifecycle management. Identify stakeholders. Collect existing documents. Agree on data protection criteria. | Project plan and stakeholder list |
| 2. Current state assessment | Interview teams, review documents, and map encryption and key management in use. | Current state summary |
| 3. Gap analysis | Compare the current state with frameworks such as NIST Special Publication (SP) 800-57, PCI DSS v4.0.1, and Federal Information Processing Standard (FIPS) 140-3. Rate and prioritize risks. | Gap analysis and risk register |
| 4. Strategy and roadmap | Define the target state. Reuse existing solutions where possible. Propose alternatives. Estimate resources and effort. | Encryption strategy and prioritized roadmap |
| 5. Vendor evaluation (optional) | Help write the Request for Proposal (RFP) and vendor questionnaires. Score and compare vendors. | Vendor evaluation matrix |
| 6. Proof of concept (optional) | Set up a Proof of Concept (POC) environment, test the shortlisted solution, document results, and prepare a cost analysis. | POC results and go or no-go recommendation |
| 7. Implementation support (optional) | Help deploy and integrate the selected solution and write operating procedures. | Runbooks and implementation guidance |

The customer and EC agree on which phases are in scope during scoping. Many engagements start with phases 1 to 4 and add later phases as a follow-on.

## Deliverables

- Current state assessment report
- Gap analysis against agreed frameworks
- Risk register with severity and priority for each finding
- Encryption strategy and target architecture
- Prioritized roadmap with resource estimates
- Executive summary for leadership
- Vendor evaluation analysis and POC results (when in scope)
- Implementation guidance and runbooks (when in scope)

## What EC needs from the customer

**Stakeholders**

- An executive sponsor who can approve scope and decisions.
- A project lead who schedules interviews and tracks actions.
- Owners for security architecture, key management, applications, databases, storage, cloud, and compliance or risk.

**Documents**

- Information security, encryption, and key management policies and standards.
- Data classification policy and any data inventory.
- Network and application architecture diagrams.
- Recent audit reports and open findings.
- A list of current encryption tools, Hardware Security Modules (HSMs), and key managers.

**Access**

- Time with stakeholders for interviews and workshops.
- Read-only access to relevant consoles or reports, when agreed.
- A secure way to exchange documents. See [Secure file sharing with EC support](../00-Working-with-EC-Support/secure-file-sharing-with-ec-support.md).
